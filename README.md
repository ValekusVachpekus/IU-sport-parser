# SportParser — автозапись на спорт Innopolis

Telegram-бот, который автоматически записывает (check-in) на спортивные занятия
на [sport.innopolis.university](https://sport.innopolis.university):

- **в момент открытия записи** — ровно за 7 дней до начала занятия;
- **по освободившемуся месту** — ловит, когда кто-то отписался.

Работает напрямую через официальный JSON API сайта (не браузер), что и быстрее, и
не похоже на бота-скрапера. Рассчитан на нескольких пользователей: каждый входит своим
аккаунтом Innopolis.

## Как это устроено

| Слой | Файл | Что делает |
|------|------|-----------|
| Конфиг | `app/config.py` | env-настройки |
| Шифрование | `app/crypto.py` | Fernet для паролей и cookie |
| БД | `app/db/` | SQLite (SQLAlchemy async): пользователи и правила |
| SSO | `app/sport/auth.py` | вход через ADFS-форму, получение session-cookie сайта |
| API | `app/sport/client.py` | check_in / расписание / профиль, релогин при 401/403 |
| Планировщик | `app/scheduler/` | резолвит правила в занятия и ставит точные джобы |
| Бот | `app/bot/` | aiogram 3: логин, добавление правил, уведомления |

**Механика записи** (подтверждено по исходникам `one-zero-eight/sport`):
запись на сессию = `POST /api/training/<training_id>/check_in`, разрешена ровно
за неделю до `training.start` и пока занятие не кончилось; свободные места =
`group.capacity − число check-in`. Лимиты сервера: ≤4 ак.ч/день, ≤2 ак.ч/день
на один вид спорта.

**Авторизация**: OAuth-клиент сайта *конфиденциальный* (client_secret есть только у
сервера), поэтому токен сами получить не можем. Вместо этого проходим вход через сам
сайт: `GET /oauth2/login` → форма ADFS (`UserName`/`Password`/`AuthMethod`) → сайт сам
меняет `code` на сессию и ставит cookie `sessionid`. Им и `csrftoken` (+ `X-CSRFToken`
на POST) аутентифицируем API. ROPC и самостоятельный обмен кода не работают
(`MSIS9622 invalid_client`).

## Запуск (VPS, Docker)

```bash
git clone <repo> && cd SportParser
cp .env.example .env

# 1) Токен бота от @BotFather → BOT_TOKEN
# 2) Свой Telegram id (через @userinfobot) и id друзей → ALLOWED_TG_IDS
# 3) Ключ шифрования:
python -m app.crypto      # вставь вывод в FERNET_KEY (или сгенерируй внутри контейнера)

docker compose up -d --build
docker compose logs -f
```

> Часовой пояс контейнера = `Europe/Moscow` (как на сайте). Тайминг открытия записи
> привязан к `training.start − 7 дней` с точностью до секунды, поэтому держите время
> VPS синхронизированным (NTP).

## Использование (в Telegram)

1. `/login` — логин и пароль Innopolis (сообщение с паролем бот удаляет; пароль
   хранится в БД в зашифрованном виде).
2. `/add` — выбрать занятие из расписания (сгруппировано по дням недели) и режим:
   - ⚡ **В момент открытия** — бьётся за место ровно при открытии записи;
   - 👀 **Ловить место** — следит и записывает при освобождении;
   - ⚡+👀 **Оба**.
3. `/rules` — список правил, включить/выключить (🟢/⚪), удалить (🗑).
4. `/cancel` — прервать текущий шаг; `/help` — все команды.

Бот пишет только при **успешной** записи. Промах в момент открытия не спамит —
watch-режим продолжает молча следить до начала занятия.

## Локальная проверка

```bash
pip install -e ".[dev]"

# Юнит-тесты (без сети):
pytest -q

# Живая проверка SSO + API на своём аккаунте:
python -m scripts.check_auth <login> <password>
```

`check_auth` печатает профиль, виды спорта и ближайшие занятия с их `training_id`,
`can_check_in`, `checked_in` — так можно убедиться, что авторизация и эндпоинты
работают, до запуска бота.

## Если SSO-логин не проходит

`auth.py` логинится через HTML-форму ADFS и забирает session-cookie сайта.
Если форма логина начнёт требовать JavaScript (форма не сабмитится чистым HTTP),
fallback — разовый headless-логин через Playwright для получения cookie, дальше всё
то же API. Этот режим не реализован — добавляется при необходимости.

Частые причины ошибки входа: неверный логин/пароль (ADFS возвращает форму повторно)
или просроченная сессия — бот сам перелогинится по сохранённым данным.

## Анти-бан

- Только официальный JSON API + браузерный `User-Agent`, одна переиспользуемая
  сессия на пользователя (без логина на каждый запрос).
- Watch-поллинг ≥45 с с джиттером; всплеск запросов — только ~2–8 с вокруг момента
  открытия записи.
- Запросы одного пользователя сериализованы (без гонок).
